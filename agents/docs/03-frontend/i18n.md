# Frontend i18n

This file tells you how to add or change a UI string in the Svelte client without breaking lint or translations.
Read it whenever your change shows text to the user.

The process side (Transifex sync, adding a language, the separate Django template flow) is in `DEVELOPER_GUIDE.md`, sections "Internationalization" and "Translation process". It is not repeated here.

## Facts

- Library: `svelte-i18n` 4.0.0. Message syntax is ICU.
- Source of truth: `mathesar_ui/src/i18n/languages/en/dict.json`. It is a flat object of 957 keys in snake case, sorted alphabetically.
- Other languages are `es`, `fr` and `ja` in sibling folders. Transifex writes those files. Do not edit them.
- Keys missing in a language fall back to `en` (`fallbackLocale` in `mathesar_ui/src/i18n/index.ts`).
- Django injects the dictionary script for the user's language, plus `en` when the language differs. `initI18n` reads it from `window.Mathesar.translations`.
- The language comes from `user.display_language`. The anonymous shared form page always starts in `en` (`mathesar_ui/src/App.svelte`).

## Add or change a string

1. Search `mathesar_ui/src/i18n/languages/en/dict.json` for an existing key with the same text and meaning. Reuse it if found.
2. Otherwise add a key. Use snake case derived from the English text, or from its purpose for long text (`add_tables_to_new_schema`).
3. Keep keys sorted. `npm run format` sorts the file for you.
4. Reference the key as a string literal.

```svelte
<script lang="ts">
  import { _ } from 'svelte-i18n';
</script>

<h1>{$_('administration')}</h1>
<TextInput placeholder={$_('name')} />
```

In a `.ts` file there is no `$` syntax. Use the store value at the time of use:

```ts
import { get } from 'svelte/store';
import { _ } from 'svelte-i18n';

toast.info(get(_)('required_hidden_columns_made_visible'));
```

Call `get(_)(...)` inside a function. A string computed at module load is not recomputed when the language changes.

### Interpolation

```json
"page_number": "Page {pageNumber}"
```

```svelte
{$_('page_number', { values: { pageNumber: page } })}
```

### Plurals

```json
"count_records": "{count, plural, one {{count} Record} other {{count} Records}}"
```

```svelte
{$_('count_records', { values: { count: totalCount } })}
```

Do not build plurals or sentences by concatenating translated fragments.

### Text that contains components or markup

Use `RichText` from `mathesar_ui/src/components/rich-text/RichText.svelte`. The dictionary string marks slots with square brackets. A slot can carry translated text in parentheses.

```json
"database_not_found": "Database with id [connectionId] is not found.",
"all_of_the_following": "[bold](all) of the following"
```

```svelte
<RichText text={$_('all_of_the_following')} let:slotName let:translatedArg>
  {#if slotName === 'bold'}
    <strong>{translatedArg}</strong>
  {/if}
</RichText>
```

- Slot names may contain letters, digits and underscores.
- `{name}` is ICU interpolation of a value. `[name]` is a `RichText` slot for a component. A string can use both.
- Never put HTML in a dictionary string and never use `{@html}` for translations.

### Text that must not be translated

Put it in `mathesar_ui/src/i18n/staticText.ts` and reference `staticText.NAME`. That file exists so that such text passes the lint rule.

### Changing or removing

- Changing the English text of a key leaves the `es`, `fr` and `ja` values as they are until translators update them. If the meaning changes, add a new key and remove the old one.
- When you delete the last use of a key, delete the key from the `en` file.

## What lint and CI enforce

CI runs `npm run lint` and `npm run check-format` (see `agents/docs/03-frontend/testing-lint.md`). The relevant rules are in `mathesar_ui/.eslintrc.cjs` and `mathesar_ui/.prettierrc`.

| Rule | Effect |
|---|---|
| `@intlify/svelte/no-raw-text` | Error on literal text in Svelte markup, and in the attributes `label`, `triggerLabel`, `aria-label`, `ariaLabel`, `title`, `placeholder`, `searchPlaceholder`. A short list of symbols and words is allowed (`ignoreText` in the config). |
| scope of that rule | It skips `mathesar_ui/src/component-library/` and `__meta__` folders. |
| `sort-keys` on `src/**/*.json` | Error when dictionary keys are not sorted. |
| `prettier-plugin-sort-json` | `npm run check-format` fails on unsorted JSON. `npm run format` fixes it. |

Not enforced:

- The lint rule does not see strings in `.ts` files or strings passed through variables and props with other names. Review those by hand.
- `mathesar_ui/scripts/i18n/check_invalid_calls.py` checks that `$_(` and `get(_)(` receive string literals. No CI job runs it. It currently fails on two existing files (`mathesar_ui/src/pages/home/HomePage.svelte` and `mathesar_ui/src/systems/table-view/table-inspector/column/SetDefaultValue.svelte`).
- `mathesar_ui/scripts/i18n/check_unused_strings.py` lists unused keys. It exits early while the first script fails.
- `mathesar_ui/scripts/i18n/resolve_dict_merge_conflicts.py` resolves merge conflicts in the `en` dictionary. Run it from the repo root.

Keep keys as string literals anyway. Both scripts and any human search rely on grepping `$_('key'`.

Nothing checks that a referenced key exists. A missing key renders as the key text. A scan of this checkout found six such keys in use: `search`, `Integer`, `UUID`, `None`, `field` and `mathesar`. After adding a string, confirm the key is present in the `en` file with the exact same spelling.

## Other places with user-facing text

- Labels in the type option forms under `mathesar_ui/src/stores/abstract-types/type-configs/` are plain English and not translated.
- The component library has hard-coded English defaults. Pass translated strings in from app code.
- Backend error messages arrive in English inside `RpcError.message`.
- Server-rendered pages (login, installation) use Django gettext and `translations/`. See `DEVELOPER_GUIDE.md`.
- Component tests get the `en` dictionary from `mathesar_ui/vitest-setup.config.ts`, so `$_` works in tests.
